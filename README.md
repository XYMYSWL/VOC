# VOC

用 Rust 写的轻量语音开黑软件，类似 Discord / Oopz 的语音频道 + 文字聊天。

## 功能

- 多语音频道，点一下就进；可以在客户端新建频道；每个频道最多 20 人，频道名旁显示人数
- 实时语音：语音激活（VAD）自动检测说话，带说话绿圈指示
- 闭麦 / 静音（Ctrl+M / Ctrl+D），右键队友可单独调音量（0–200%）
- 服务器全局文字聊天、进出提示
- **端到端加密**：语音（直连和服务器中转）与聊天服务器都看不到；ML-DSA-65 身份签名防中间人，身份变化会警告，可核对安全码
- **授权码登录**：授权码由服务端生成，可设有效期、随时吊销（在线的人立即被踢）；同一授权码只能一处在线
- **自建服务器**：客户端可填任意服务器地址，并保存多个服务器到「我的服务器」列表
- **ML-KEM-768 抗量子加密**：语音与聊天全程加密，授权码双向认证，防中间人
- **抗审查 / 抗 DPI**：线路上无任何明文特征，随机填充，对探测不响应；UDP 被封时自动切到加密 TCP
- **界面**：深色主题，频道人数、直连质量、共享状态一目了然；设置分「音频 / 降噪 / 视频 / 网络 / 加密 / 关于」六页
- **屏幕共享**：480P / 720P / 1080P × 30 / 60 帧可选，端到端加密，能直连的观看者走 P2P
- **GPU 硬件编码**：自动挑最省带宽的编码器（AV1 > HEVC > H.264，按所有观看者都能解的来协商），可手动选用哪块 GPU（NVIDIA / AMD / Intel）或纯软件编码；解码可选硬解 / 软解
- **进场 / 退场音效**：有人进出你所在的频道时播放提示音，音量可调、可关闭
- **检查更新**：启动时（可关）查询 GitHub Releases，有新版在顶栏提示
- **MSIX 安装包**：双击安装，开始菜单启动，自动添加防火墙规则
- **P2P 直连语音**：同频道成员 UDP 打洞直连（IPv4 / IPv6，UPnP 端口映射，端口预测），成员旁直接显示直连延迟；打不通的人自动走服务器中转
- **Opus 编码**：24 kbps，带内 FEC + 丢包补偿，带宽约为原来的一半、音质更好
- 延迟（ping）与传输方式（UDP 直连 / TCP 隧道）显示
- **AI 降噪**：内置免费的 RNNoise（默认开启），并预留插件接口可接入 **Krisp**
- 麦克风 / 扬声器设备选择、增益、输出音量、麦克风测试（自我回放）
- 记住服务器、昵称、（可选）授权码和音频设置

## 架构

```
crates/
  voc-proto/   共享协议：握手与加密（crypto.rs）、授权码（auth.rs）、P2P 密钥（p2p.rs）、消息
  voc-server/  tokio 服务器：授权码管理、TCP 控制 + UDP 语音转发（SFU，只转发不混音）
  voc-client/  egui 桌面客户端 + cpal 音频 + 降噪 + 屏幕共享（video.rs）
  voc-denoise-example/  降噪插件接口的最小示例（测试用）
plugins/
  voc_denoise.h     降噪插件 C 接口
  krisp_shim/       Krisp 适配层模板（C++，拿到 SDK 后填 TODO）
```

- **控制通道**：TCP，握手后每帧加密（帧内是 JSON）。
- **语音通道**：UDP，与 TCP 同一个端口号，每包加密 + 混淆。服务器只转发给同频道、未静音的成员；UDP 不通时语音走 TCP 帧。
- **音频**：采集 → 48 kHz 单声道 10 ms 帧 → 降噪（RNNoise / Krisp 插件）→ 降采样到 16 kHz → 20 ms 一帧 → Opus 24 kbps → 直连 / 服务器中转。
  接收端每个说话人一个 Opus 解码器（去重、丢包时用 FEC 恢复或 PLC 补帧）和抖动缓冲（预缓冲 60 ms、上限 200 ms），混音后软削波再升采样到声卡。
- libopus 从源码编译（用 VS 生成工具自带的 cmake），其余都是纯 Rust 依赖。

## 安装（Windows 客户端）

到 [Releases](https://github.com/XYMYSWL/VOC/releases) 下载最新的 `VOC-<版本>.msix`、`VOC.cer`、`install.ps1`、`安装VOC.cmd`，
放同一个文件夹，双击 **`安装VOC.cmd`**（会请求管理员权限）。

- 安装包是**自签名**的：脚本会先把 `VOC.cer` 导入本机「受信任的人」证书库，再安装 MSIX。只需要做一次，以后升级直接双击新的 `.msix` 即可。
- 不想装证书？下载 `VOC客户端.zip`，解压直接运行 `voc-client.exe`（绿色版）。
- 卸载：开始菜单右键 VOC → 卸载。
- 需要 Windows 10 1903 及以上。

## 编译

需要 Rust（MSVC 工具链）+ Visual Studio 生成工具（你的电脑上已经有了）：

```powershell
cargo +stable-x86_64-pc-windows-msvc build --release
```

或者直接运行 `.\build.ps1`：Windows 客户端 / 服务端、MSIX 安装包（首次会自动生成自签名证书，私钥存在
`%USERPROFILE%\.voc-signing\`，不在仓库里）、Linux 服务端安装包全部输出到 `dist\`。

> 注：Windows 有 260 字符路径限制（libopus 的 MSBuild 尤其敏感）。项目放在很深的目录时，
> 可以在**仓库外层目录**建一个 `.cargo/config.toml`（Cargo 会自动向上合并读取，不会提交进 Git），写本机专用设置：
>
> ```toml
> [build]
> target-dir = "C:/voc-target"          # 短路径
> [env]
> CMAKE = "C:/Program Files (x86)/Microsoft Visual Studio/2022/BuildTools/Common7/IDE/CommonExtensionsMicrosoft/CMake/CMake/bin/cmake.exe"
> NASM = "C:/Program Files/NASM/nasm.exe" # openh264 汇编优化（软件编码快约 10 倍）：winget install NASM.NASM
> ```
>
> 默认的 `windows-gnu` 工具链缺少汇编器，编不过 `windows-sys`，请用 MSVC 工具链。
> 做 MSIX 安装包需要 Windows SDK（自带 `makeappx.exe` / `signtool.exe`）。

## 使用

1. 一台机器运行服务器（需要公网 IP / 端口映射，或者同一局域网，或用 ZeroTier/Tailscale 组网）：

   ```powershell
   .\voc-server.exe --name "我的 VOC 服" --channels "大厅,五排,双排,挂机"
   ```

   放行 **TCP 和 UDP** 的 7878 端口（可用 `--bind 0.0.0.0:端口` 修改）。

2. 给每个人生成授权码（服务器运行时也能执行，立即生效）：

   ```powershell
   .\voc-server.exe gen-code --note 小明                # 生成 1 个，备注「小明」
   .\voc-server.exe gen-code -n 5 --days 30 --note 群友  # 生成 5 个，30 天有效
   .\voc-server.exe list-codes                         # 查看全部
   .\voc-server.exe revoke-code <ID>                   # 吊销（在线的人 5 秒内被踢）
   .\voc-server.exe restore-code <ID>                  # 恢复
   ```

   授权码形如 `KH-XXXXXXXX-XXXX-XXXX-XXXX-XXXX-XXXX-XX`，**只在生成时显示一次**，请私下发给对应的人。
   服务器在 `voc-codes.json` 里只保存它的哈希派生值，但这个文件仍可用来冒充用户登录，请勿外泄。

3. 每个人运行 `voc-client.exe`，填服务器地址、昵称、授权码；可点「💾 保存」存进「我的服务器」列表。进入后点频道即可开黑。
4. 第一次用先点「⚙ 设置」看电平条，把灵敏度阈值调到「说话时超过白线、不说话时低于白线」。

## 部署到 Linux 服务器（推荐）

`dist\voc-server-linux.tar.gz` 是现成的安装包：x86_64 和 arm64 两种 CPU 的静态编译程序 + 一键安装脚本，
支持带 systemd 的 64 位 Linux（Ubuntu 18.04+、Debian 10+、CentOS/Rocky 8+ 等）。

```powershell
scp dist\voc-server-linux.tar.gz root@你的服务器IP:/root/
ssh root@你的服务器IP
```

```bash
tar xzf voc-server-linux.tar.gz && cd voc-server-linux
sudo bash install.sh --name "我的 VOC 服"        # 可加 --port 443 / --channels "大厅,五排"
```

安装脚本会：创建专用的 `voc` 系统用户、装成开机自启的 systemd 服务（崩溃自动重启、权限加固）、
自动放行 ufw / firewalld 端口、开启 NTP 时间同步，并生成第一个授权码。
云服务器还需要在控制台「安全组」里放行 **TCP 和 UDP** 端口。

之后在服务器上用 `sudo voc gen-code --note 小明`、`sudo voc list-codes`、`sudo voc revoke-code <ID>`、
`sudo voc status / logs / restart / config` 管理。升级：`sudo bash install.sh --upgrade`（保留授权码和配置）；
卸载：`sudo bash uninstall.sh`（加 `--purge` 连授权码一起删）。详见包内 `安装说明.txt`。

## 降噪：RNNoise 与 Krisp

设置 → 「AI 降噪」三选一：

- **关闭**
- **RNNoise（内置，免费，默认）**：开源神经网络降噪，对风扇、空调、键盘这类背景噪音效果好；
  对很"嘶"的白噪音削减有限。
- **Krisp / 外部插件**：从 DLL 加载第三方降噪。

### 接入 Krisp

Krisp SDK 不公开下载，需要先向 Krisp 申请开发者账号和商业授权。拿到 SDK 后：

1. 打开 `plugins/krisp_shim/krisp_shim.cpp`，按你那个 SDK 版本的头文件和示例，把标了 `TODO(krisp)` 的
   4 处（全局初始化、加载模型并创建 48 kHz / 10 ms 会话、处理一帧、释放）换成真实调用。
2. 编译出 `voc_krisp.dll`（`plugins/krisp_shim/CMakeLists.txt`，或直接用 MSVC：
   `cl /LD /EHsc /std:c++17 /utf-8 krisp_shim.cpp <Krisp 的 .lib> /Fe:voc_krisp.dll`）。
3. 把 `voc_krisp.dll` 和 Krisp SDK 自带的 DLL 放同一个目录。
4. 客户端设置里选「Krisp / 外部插件」，填 DLL 路径和模型文件路径，点「加载插件」。

插件出错时客户端会自动停用插件、透传原声，不会把你的麦克风弄没声。
插件接口见 `plugins/voc_denoise.h`，任何降噪库都可以照着接进来。

## 屏幕共享

进入语音频道后，左下角「🖥 共享屏幕」：选显示器、分辨率（480P / 720P / 1080P）、帧率（30 / 60），点「开始共享」。
同频道的人名字旁会出现「📺 观看 1080p60」，点一下弹出可缩放的画面窗口，标题栏显示实际分辨率和帧率。

- **管线**：Windows Graphics Capture 采集 → 缩放 + 颜色转换（多线程）→ 编码（GPU 硬件编码器或 openh264）
  → 整帧端到端加密 → 切成 ≤1.1 KB 的分片 → 能直连的观看者 P2P 直发，其余经服务器中转（UDP 不通时走 TCP 隧道）。
- **低延迟**：不重传；丢了分片就丢掉这一帧，接收端向共享者请求关键帧（最多每 300 ms 一次），共享者另每 10 秒兜底一个关键帧。
  采集和解码都只保留最新画面，跟不上就丢旧帧，不会越积越多。
- **保帧率**：码率控制不跳帧，画面变化剧烈时降低清晰度来维持你选的帧率。
- **省资源**：没人观看时不编码、不发送；服务器只转发给正在看的人，已 P2P 直连的不经过服务器。
- **端到端加密**：视频用发送者密钥派生出的独立视频密钥加密（与语音的计数器互不影响），服务器只看到密文。
- **实测**（本机 1920×1080 屏幕，经两个真实客户端链路 P2P 直连，接收端解码）：720p60 和 1080p60 均稳定 60 fps，
  1080p 编码约 13 ms/帧。实际帧率取决于 CPU 和画面变化程度。
- 码率（每位观看者，H.264 基准；HEVC × 0.75，AV1 × 0.6）：480P 0.9 / 1.4 Mbps，720P 2 / 3 Mbps，1080P 3.5 / 5.5 Mbps（30 / 60 帧）。
- **实测硬件编码**：1080p60 用 NVIDIA AV1 约 3 ms/帧（openh264 约 11 ms/帧）。
- 目前只支持共享整个显示器，不含系统声音；需要 Windows 10 1903 及以上。

### 编码器与解码器

- **自动（推荐）**：每个客户端登录时上报自己能解哪些格式，共享者在**所有观看者都能解**的格式里挑最省带宽的：
  AV1（同画质约 0.6 倍码率）> HEVC（约 0.75 倍）> H.264。有硬件编码器就用 GPU，否则 openh264 软件编码。
- **手动**：设置 → 视频（或共享窗口里）可以指定用哪块 GPU 编码（如 NVIDIA AV1 / AMD HEVC / Intel H.264），或选「软件编码」。
  选的格式有观看者不支持时会自动降到大家都能解的格式。
- **解码**：设置 → 视频 → 「硬解 / 软解」。硬解用 GPU（DXVA），软解用 CPU。AV1 只在显卡支持 AV1 硬解时才会被协商使用。
- 共享窗口和观看窗口会显示当前实际使用的编码器 / 解码器；GPU 编码出错时会自动切回软件编码，不会中断共享。
- 硬件编解码通过 Windows Media Foundation 实现，不需要额外安装驱动以外的东西（HEVC 软解需要「HEVC 视频扩展」）。

## P2P 直连与省服务器

设置 → 网络 → 「P2P 直连语音」（默认开启）。

- 同频道里都开了 P2P 的成员之间，客户端会自动 **UDP 打洞**：候选地址包括服务器看到的公网地址、局域网 IPv4、IPv6。
  打通后语音直接互发，**完全不经过服务器**；成员旁边显示「⇄ 23 ms」表示已直连及直连延迟（绿 < 80 ms，黄 < 200 ms，红更高）。
- **打洞增强**：
  - **UPnP**：自动请求家用路由器做 UDP 端口映射（很多路由器默认开启），把映射出的公网地址加入候选，对方可以直接打进来；
    路由器自己没有公网 IP（运营商级 NAT）时自动跳过；断开时删除映射。
  - **端口预测**：2 秒还没打通，就顺带试对方公网端口上下各 8 个端口（很多对称型 NAT 按顺序分配端口）。
  - 对方地址变化（换网络、UPnP 映射成功）时立即重新快速打洞；从意外地址收到合法打洞包也会直接采用（对端反射地址）。
- 仍打不通的成员（两边都是严格的对称 NAT 等）自动走服务器中转，用户无感知；直连断开 4 秒后也会自动回到中转。
- **直连不稳自动切中继**：每 0.5 秒测一次直连的延迟 / 丢包 / 抖动（统计最近 10 秒）。丢包 ≥15%、平均延迟 >350 ms 或抖动 >80 ms
  时自动改走服务器中转，名字下显示黄色「不稳·中转」；之后至少中转 30 秒，并且连续稳定 10 秒才切回直连，避免来回跳。
  直连断过的人重新打通后也先中转观察一段时间。链路在中转期间继续测量，右键成员可看实时数值。
  服务器只给「没直连的人」转发，频道里只剩自己时完全不发语音。
- 直连包用**两人之间的端到端成对密钥**加密（见下文「端到端加密」），外观和服务器流量一样是全随机字节。
- **代价**：同频道开启了 P2P 的成员能看到你的 IP 地址。不想暴露就关掉这个开关，只走服务器中转（服务器也不会把你的地址给任何人）。
- **按上行带宽分配**（设置 → 网络 →「直连上行预算」，默认 15 Mbps，1–100 可调）：直连要给每个人各发一份，
  所以客户端按预算决定直连哪些人——**语音优先**（约 0.06 Mbps/人），剩下的给屏幕共享画面（按码率 ×1.05 计）；
  只要有人不直连就要多传一份给服务器，这份也计入预算；同等条件下优先直连延迟低的人。语音和画面分开分配，分别告诉服务器不用再转发给谁。
  例：20 人频道语音全部直连约 1.1 Mbps；共享 1080p60 时 15 Mbps 预算大约够直连 1–2 个观看者，其余观看者经服务器（服务器只收你 1 份再分发）。
  名字旁「⇄ 23 ms」彩色 = 正在直连；灰色 = 已打通但超出预算，你的声音经服务器转给他。

带宽估算（每路说话的人，含 IP/UDP 与加密开销）：原 ADPCM ~94 kbps → 现 Opus ~53 kbps。
服务器带宽 ≈ 只为「打不通直连的人」转发的那部分。

## 端到端加密

细节见 `crates/voc-proto/src/e2e.rs` 文件头注释。**服务器只转发密文，听不到语音、看不到聊天**——包括经服务器中转的语音。

- **身份**：每台客户端第一次运行时生成一个长期 **ML-DSA-65**（FIPS 204，抗量子签名）身份密钥，保存在本机。
  登录后公布：身份公钥 + 本次会话的 ML-KEM-768 公钥 + 对「昵称 | 会话公钥」的签名。服务器改名、换公钥都会验签失败。
- **成对密钥**：每两个在线用户之间用 ML-KEM-768 封装出共享秘密，封装方还要对「对方公钥 | 密文」签名。
  服务器只转交公钥、密文和签名，**算不出成对密钥，也冒充不了任何一方**。
- **语音**：每人有一把自己的「发送者密钥」，用成对密钥加密后发给同频道每个人；每帧 Opus 只加密一次，所有接收者共用同一份密文，
  所以服务器中转的也只是密文。**频道成员一变就换新密钥**：离开的人听不到以后的语音，新来的人听不到以前的语音。
  帧计数器受认证保护，恶意服务器重放旧语音包会被丢弃。
- **聊天**：每条消息对每个接收者单独加密，服务器只转交密文。
- **防中间人**：
  - 第一次见到某人时记住他的身份（TOFU）。以后同一个昵称带着**不同的身份**出现（换了电脑，或者有人冒充，包括服务器），
    客户端会在聊天区警告、名字旁显示红色「⚠」，并**暂停与其所有加密通信**（不发语音密钥、不发聊天）。
  - 右键成员可看到对方的**安全码**（30 位数字）；请对方在「设置 → 我的安全码」里念给你听，一致即可点「已核对，信任新身份」。
  - 成员旁的「🔒」表示与他的端到端加密已建立。

**这部分的限制**

- 服务器仍能看到**元数据**：谁在线、谁和谁在同一频道、谁在什么时候说话（包的时间和大小）、聊天发给了谁。
- 第一次见面的身份是自动信任的：如果服务器在你**第一次**见到某人时就冒充他，只有核对安全码才能发现。重要的人建议核对一次。
- 身份私钥以明文保存在本机配置文件里；换电脑或删除配置后身份会变，朋友那边会看到「身份已变化」的警告。

## 安全与抗审查

**传输层加密与认证**（细节见 `crates/voc-proto/src/crypto.rs` 文件头注释）

- 每次连接都新生成 **ML-KEM-768**（FIPS 203，抗量子）临时密钥对做密钥交换，有前向安全：以后授权码泄露，也解不开以前录下的流量。
- 授权码派生的预共享密钥参与全部密钥派生，相当于**双向认证**：没有正确授权码就算不出会话密钥，中间人既解不开也伪造不了；
  授权码的秘密部分从不在网络上传输。
- 对称加密用 ChaCha20-Poly1305（256 位）。TCP 帧和 UDP 包都有认证，UDP 用 64 包滑动窗口防重放。

**抗 DPI / 抗探测**

- 线路上**没有任何明文字段**：没有魔数、版本号、用户 ID、长度。ML-KEM 的公钥和密文有统计特征，所以也整体加密；
  UDP 包计数器也做了掩码（类似 QUIC 的头部保护）。在不知道授权码的观察者看来，所有字节都是随机数。
- 握手包、TCP 帧、UDP 包都有**随机填充**，长度不固定。
- 服务器对认证不了的连接（错误授权码、HTTP/TLS 探测、随机数据、重放的握手）**一个字节都不回**，
  吞掉数据 20–60 秒后再关闭，主动探测拿不到任何特征。握手带时间戳和盐值缓存，录下来重放无效。
- **UDP 被封或被限速**时（4 秒收不到回应），语音自动改走已加密的 TCP 连接，顶栏显示「🔒 TCP 隧道」；UDP 恢复后自动切回。

**低延迟**

- 默认 UDP 直连，20 ms 一帧，接收端只预缓冲 60 ms，没有额外的重传或握手往返。
- TCP 回退时收到的语音在读线程里直接解码送进混音器，不经过界面线程；TCP 已关闭 Nagle（`TCP_NODELAY`）。

**已知限制（请知悉）**

- 「全随机」流量本身也可能被部分国家级防火墙用熵值等启发式规则识别和干扰（例如 GFW 自 2021 年起对「完全加密流量」的检测）。
  目前的设计能挡住特征匹配和主动探测，但不能保证在最严格的网络环境下不被封锁；更强的伪装（例如套一层真实 TLS 并跑在 443 端口）可以作为下一步。
- 客户端与服务器时钟差需在 10 分钟以内，否则握手会被当成重放（客户端会提示）。
- 勾选「在本机记住授权码」时，授权码以明文保存在 VOC 的本地配置文件里。
