# 服务端部署

[← 返回 README](../README.md)

服务端很轻：只做登录认证和转发加密后的数据（听不到语音、看不到聊天），1 核 / 512 MB 的 VPS 就够用。
运行状态：`sudo voc status`（在线的人、谁在共享、转发带宽、NAT 探测端口、封禁中的 IP、现在几对人语音直连成功和启动以来的直连率）。
服务器带宽小（例如 2 Mbps）时限制转发屏幕共享画面的总带宽：`sudo voc video-limit 1.5`（单位 Mbps，可带小数；
`sudo voc video-limit off` 不限，不带参数查看当前值）。改完会重启服务，在线的人断开一两秒后自动重连。超出上限时部分观看者自动改看「流畅」。
安装时也可以直接带 `--max-video-mbps 1.5`。
服务器连不上 GitHub 时，安装 / 升级脚本会自动改走国内镜像（见下面「校验」）。

> **0.6.0 和 0.5.x 不兼容**：0.6 的服务器只让 0.6 的客户端登录（旧客户端会提示更新）。升级顺序：先升级服务器，再让大家更新客户端。
> 要退回 0.5.1：服务器 `sudo voc upgrade v0.5.1`，客户端从 GitHub Release 下载 0.5.1（两边都要退）。退回后画面限速要重新用 `voc config` 写进 `VOC_EXTRA_ARGS`。

需要放行 **TCP 和 UDP** 的同一个端口（默认 7878）。另外建议放行 **UDP 7879**（主端口 + 1）：NAT 探测端口，帮客户端准确判断 NAT 类型、提高直连成功率；没放行也能用。服务器参数 `--probe-port 端口` 可改，`--probe-port 0` 不开。

服务器有**第二个公网 IP** 时，可以加 `--probe2 第二个IP`（云服务器上绑的是内网 IP 时写 `--probe2 内网IP/公网IP`），在第二个 IP 上也开探测端口（同一个端口号，同样要放行 UDP）。
客户端能更准地判断 NAT：换了对方 IP 映射变不变、没联系过的地址能不能进来。只有一个公网 IP 就不用加。

0.6.2 起，客户端网络断了一下 / 换了网络时，服务器会先保留这个人 20 秒（别人看不到他离开，语音照常转发），客户端带着恢复凭证重连就接着用；
20 秒没回来才算离开。主动退出 VOC 的人马上移除。`voc status` 里多一行「最近 N 天按天的语音直连率」（按 UTC 日期，只记次数），
数据存在授权码文件旁边的 `*.p2p-days.txt`，留 7 天。

## Linux（推荐）

### 一键安装 / 升级

```bash
curl -fsSL https://github.com/XYMYSWL/VOC/releases/latest/download/get.sh | sudo bash
```

- 没装过就全新安装；装过就自动升级（保留授权码和配置）。
- 带参数：`... | sudo bash -s -- --port 443 --name "我的 VOC 服"`（参数同下面的 `install.sh`）。
- 装指定版本：`... | sudo VOC_VERSION=v0.2.2 bash`。
- 脚本会核对 GitHub 公布的 SHA-256，对不上就停止。
- **校验（0.6 起更严格）**：安装包如果是经国内镜像 / 自定义地址下载的，又取不到 GitHub 公布的 SHA-256（服务器连不上 GitHub 接口），
  脚本会停止，免得装上被篡改的程序。这时在能上 GitHub 的电脑打开 Release 页面，抄下 `voc-server-linux.tar.gz` 的 sha256，然后
  `... | sudo VOC_SHA256=<校验值> bash`；确实要冒险跳过校验：`... | sudo VOC_INSECURE=1 bash`。直接从 GitHub 下载的不受影响。
- 装好之后升级只要 `sudo voc upgrade`，看版本用 `sudo voc version`。

### 离线安装（服务器访问不了 GitHub 时）

Release 里的 `voc-server-linux.tar.gz` 是现成的安装包：x86_64 和 arm64 两种 CPU 的静态编译程序 + 一键安装脚本，
支持带 systemd 的 64 位 Linux（Ubuntu 18.04+、Debian 10+、CentOS/Rocky 8+ 等）。

```powershell
scp voc-server-linux.tar.gz root@你的服务器IP:/root/
ssh root@你的服务器IP
```

```bash
tar xzf voc-server-linux.tar.gz && cd voc-server-linux
sudo bash install.sh --name "我的 VOC 服"        # 可加 --port 443 / --channels "大厅,五排"
```

安装脚本会：创建专用的 `voc` 系统用户、装成开机自启的 systemd 服务（崩溃自动重启、权限加固）、
自动放行 ufw / firewalld 端口、开启 NTP 时间同步，并生成第一个授权码。
云服务器还需要在控制台「安全组」里放行 **TCP 和 UDP** 端口。

之后在服务器上用 `sudo voc gen-code --note 小明`、`sudo voc list-codes`、`sudo voc revoke-code <ID>`、
`sudo voc status / logs / restart / config`、`sudo voc video-limit 1.5` 管理；换服务器时用 `sudo voc export-users > 授权码备份.txt` 导出、
新服务器上 `sudo voc import-users 授权码备份.txt` 导入授权码。升级：`sudo bash install.sh --upgrade`（保留授权码和配置）；
卸载：`sudo bash uninstall.sh`（加 `--purge` 连授权码一起删）。详见包内 `安装说明.txt`。

## Windows

1. 一台机器运行服务器（需要公网 IP / 端口映射，或者同一局域网，或用 ZeroTier/Tailscale 组网）：

   ```powershell
   .\voc-server.exe --name "我的 VOC 服" --channels "大厅,五排,双排,挂机"
   ```

   放行 **TCP 和 UDP** 的 7878 端口（可用 `--bind 0.0.0.0:端口` 修改）。

2. 给每个人生成授权码（服务器运行时也能执行，立即生效）：

   ```powershell
   .\voc-server.exe gen-code --note 小明                # 生成 1 个，备注「小明」
   .\voc-server.exe gen-code -n 5 --days 30 --note 群友  # 生成 5 个，30 天有效
   .\voc-server.exe list-codes                         # 查看全部
   .\voc-server.exe revoke-code <ID>                   # 吊销（在线的人 5 秒内被踢）
   .\voc-server.exe restore-code <ID>                  # 恢复
   .\voc-server.exe export-users > 授权码备份.txt       # 换服务器：导出全部授权码（用你设的密码加密）
   .\voc-server.exe import-users 授权码备份.txt         # 在新服务器上导入，大家原来的授权码照样能用
   ```

   授权码形如 `KH-XXXXXXXX-XXXX-XXXX-XXXX-XXXX-XXXX-XX`，**只在生成时显示一次**，请私下发给对应的人。
   服务器在 `voc-codes.json` 里只保存它的哈希派生值，但这个文件仍可用来冒充用户登录，请勿外泄。


## 端口和网络

- 云服务器除了系统防火墙，还要在控制台「安全组」里放行 **TCP 和 UDP** 端口。
- 没有公网 IP 时，可以用端口映射，或者大家在同一个局域网 / 用 ZeroTier、Tailscale 组网。
- 想换端口：Linux 安装时加 `--port 443`，Windows 用 `--bind 0.0.0.0:端口`。
