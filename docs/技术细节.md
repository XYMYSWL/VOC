## 完整功能列表

- 多语音频道，点一下就进；可以在客户端新建频道；每个频道最多 20 人，频道名旁显示人数
- 实时语音：语音激活（VAD）自动检测说话，带说话绿圈指示
- 闭麦 / 静音全局快捷键（默认 Ctrl+M / Ctrl+D，可自定义，游戏里也有效，按下有提示音），右键队友可单独调音量（0–200%）
- 服务器全局文字聊天、进出提示；**私聊**（文字和图片，只发给对方）；**@提及**（不在前台时弹 Windows 通知、托盘红点）；**表情回应**
- **端到端加密**：语音（直连和服务器中转）与聊天服务器都看不到；ML-DSA-65 身份签名防中间人，身份变化会警告，可核对安全码
- **授权码登录**：授权码由服务端生成，可设有效期、随时吊销（在线的人立即被踢）；同一授权码只能一处在线
- **自建服务器**：客户端可填任意服务器地址，并保存多个服务器到「我的服务器」列表
- **ML-KEM-768 抗量子加密**：语音与聊天全程加密，授权码双向认证，防中间人
- **抗审查 / 抗 DPI**：线路上无任何明文特征，随机填充，对探测不响应；UDP 被封时自动切到加密 TCP
- **界面**：深色主题，频道人数、直连质量、共享状态一目了然；设置分「音频 / 降噪 / 视频 / 网络 / 加密 / 关于」六页
- **屏幕共享**：480P / 720P / 1080P × 30 / 60 帧可选，端到端加密，能直连的观看者走 P2P
- **GPU 硬件编码**：自动挑最省带宽的编码器（AV1 > HEVC > H.264，按所有观看者都能解的来协商），可手动选用哪块 GPU（NVIDIA / AMD / Intel）或纯软件编码；解码可选硬解 / 软解
- **进场 / 退场音效**：有人进出你所在的频道时播放提示音，音量可调、可关闭
- **一键安装 / 一键更新**：单个 `VOC-Setup.exe`（内含签名的 MSIX），双击安装，开始菜单启动，自动添加防火墙规则；有新版时客户端里点一下就更新
- **P2P 直连语音**：同频道成员 UDP 打洞直连（IPv4 / IPv6，UPnP / PCP / NAT-PMP 端口映射，端口预测），成员旁直接显示直连延迟；打不通的人自动走服务器中转
- **Opus 编码**：24 kbps（低带宽模式 12 kbps），带内 FEC + 丢包补偿
- **低带宽模式**、**网络自检**、观看屏幕共享时可选 **原画 / 流畅**
- 延迟（ping）与传输方式（UDP 直连 / TCP 隧道）显示
- **AI 降噪**：内置免费的 RNNoise（默认开启），并预留插件接口可接入 **Krisp**
- 麦克风 / 扬声器设备选择、增益、输出音量、麦克风测试（自我回放）
- 记住服务器、昵称、（可选）授权码和音频设置

## 架构

```
crates/
  voc-proto/   共享协议：握手与加密（crypto.rs）、授权码（auth.rs）、P2P 密钥（p2p.rs）、消息
  voc-server/  tokio 服务器：授权码管理、TCP 控制 + UDP 语音转发（SFU，只转发不混音）
  voc-client/  egui 桌面客户端 + cpal 音频 + 降噪 + 屏幕共享（video.rs）
  voc-denoise-example/  降噪插件接口的最小示例（测试用）
plugins/
  voc_denoise.h     降噪插件 C 接口
  krisp_shim/       Krisp 适配层模板（C++，拿到 SDK 后填 TODO）
```

- **控制通道**：TCP，握手后每帧加密（帧内是 JSON）。
- **语音通道**：UDP，与 TCP 同一个端口号，每包加密 + 混淆。服务器只转发给同频道、未静音的成员；UDP 不通时语音走 TCP 帧。
- **音频**：采集 → 48 kHz 单声道 10 ms 帧 → 降噪（RNNoise / Krisp 插件）→ 降采样到 16 kHz → 20 ms 一帧 → Opus 24 kbps → 直连 / 服务器中转。
  接收端每个说话人一个 Opus 解码器（去重、丢包时用 FEC 恢复或 PLC 补帧）和抖动缓冲（预缓冲 60 ms、上限 200 ms），混音后软削波再升采样到声卡。
- libopus 从源码编译（用 VS 生成工具自带的 cmake），其余都是纯 Rust 依赖。

## 安全与抗审查

**传输层加密与认证**（细节见 `crates/voc-proto/src/crypto.rs` 文件头注释）

- 每次连接都新生成 **ML-KEM-768**（FIPS 203，抗量子）临时密钥对做密钥交换，有前向安全：以后授权码泄露，也解不开以前录下的流量。
- 授权码派生的预共享密钥参与全部密钥派生，相当于**双向认证**：没有正确授权码就算不出会话密钥，中间人既解不开也伪造不了；
  授权码的秘密部分从不在网络上传输。
- 对称加密用 ChaCha20-Poly1305（256 位）。TCP 帧和 UDP 包都有认证，UDP 用 64 包滑动窗口防重放。

**抗 DPI / 抗探测**

- 线路上**没有任何明文字段**：没有魔数、版本号、用户 ID、长度。ML-KEM 的公钥和密文有统计特征，所以也整体加密；
  UDP 包计数器也做了掩码（类似 QUIC 的头部保护）。在不知道授权码的观察者看来，所有字节都是随机数。
- 握手包、TCP 帧、UDP 包都有**随机填充**，长度不固定。
- 服务器对认证不了的连接（错误授权码、HTTP/TLS 探测、随机数据、重放的握手）**一个字节都不回**，
  吞掉数据 20–60 秒后再关闭，主动探测拿不到任何特征。握手带时间戳和盐值缓存，录下来重放无效。
- **UDP 被封或被限速**时（4 秒收不到回应），语音自动改走已加密的 TCP 连接，顶栏显示「🔒 TCP 隧道」；UDP 恢复后自动切回。

**低延迟**

- 默认 UDP 直连，20 ms 一帧，接收端只预缓冲 60 ms，没有额外的重传或握手往返。
- TCP 回退时收到的语音在读线程里直接解码送进混音器，不经过界面线程；TCP 已关闭 Nagle（`TCP_NODELAY`）。

**已知限制（请知悉）**

- 「全随机」流量本身也可能被部分国家级防火墙用熵值等启发式规则识别和干扰（例如 GFW 自 2021 年起对「完全加密流量」的检测）。
  目前的设计能挡住特征匹配和主动探测，但不能保证在最严格的网络环境下不被封锁；更强的伪装（例如套一层真实 TLS 并跑在 443 端口）可以作为下一步。
- 客户端与服务器时钟差需在 10 分钟以内，否则握手会被当成重放（客户端会提示）。
- 勾选「在本机记住授权码」时，授权码以明文保存在 VOC 的本地配置文件里。

## 端到端加密

细节见 `crates/voc-proto/src/e2e.rs` 文件头注释。**服务器只转发密文，听不到语音、看不到聊天**——包括经服务器中转的语音。

- **身份**：每台客户端第一次运行时生成一个长期 **ML-DSA-65**（FIPS 204，抗量子签名）身份密钥，保存在本机。
  登录后公布：身份公钥 + 本次会话的 ML-KEM-768 公钥 + 对「昵称 | 会话公钥」的签名。服务器改名、换公钥都会验签失败。
- **成对密钥**：每两个在线用户之间用 ML-KEM-768 封装出共享秘密，封装方还要对「对方公钥 | 密文」签名。
  服务器只转交公钥、密文和签名，**算不出成对密钥，也冒充不了任何一方**。
- **语音**：每人有一把自己的「发送者密钥」，用成对密钥加密后发给同频道每个人；每帧 Opus 只加密一次，所有接收者共用同一份密文，
  所以服务器中转的也只是密文。**频道成员一变就换新密钥**：离开的人听不到以后的语音，新来的人听不到以前的语音。
  帧计数器受认证保护，恶意服务器重放旧语音包会被丢弃。
- **聊天**：每条消息对每个接收者单独加密，服务器只转交密文。
- **防中间人**：
  - 第一次见到某人时记住他的身份（TOFU）。以后同一个昵称带着**不同的身份**出现（换了电脑，或者有人冒充，包括服务器），
    客户端会在聊天区警告、名字旁显示红色「⚠」，并**暂停与其所有加密通信**（不发语音密钥、不发聊天）。
  - 右键成员可看到对方的**安全码**（30 位数字）；请对方在「设置 → 我的安全码」里念给你听，一致即可点「已核对，信任新身份」。
  - 成员旁的「🔒」表示与他的端到端加密已建立。

**这部分的限制**

- 服务器仍能看到**元数据**：谁在线、谁和谁在同一频道、谁在什么时候说话（包的时间和大小）、聊天发给了谁。
- 第一次见面的身份是自动信任的：如果服务器在你**第一次**见到某人时就冒充他，只有核对安全码才能发现。重要的人建议核对一次。
- 身份私钥以明文保存在本机配置文件里；换电脑或删除配置后身份会变，朋友那边会看到「身份已变化」的警告。

## P2P 直连与省服务器

设置 → 网络 → 「P2P 直连语音」（默认开启）。

- 同频道里都开了 P2P 的成员之间，客户端会自动 **UDP 打洞**：候选地址包括服务器看到的公网地址、局域网 IPv4、IPv6。
  打通后语音直接互发，**完全不经过服务器**；成员旁边显示「⇄ 23 ms」表示已直连及直连延迟（绿 < 80 ms，黄 < 200 ms，红更高）。
- **打洞增强**：
  - **端口映射**：依次尝试 UPnP IGD、PCP（RFC 6887）、NAT-PMP（RFC 6886），哪个成功用哪个，请家用路由器把 VOC 的 UDP 端口映射到公网，
    映射出的公网地址加入候选，对方可以直接打进来。PCP / NAT-PMP 发给默认网关（GetAdaptersAddresses 查到的）的 5351 端口，
    250 ms 起重试 3 次。路由器自己的外网地址是内网 / 100.64.0.0/10（运营商级 NAT）时映射没用，记下来给网络自检看。
    租期 1 小时，过半就续；断开时删除映射。
  - **NAT 类型探测**：服务器另开一个 UDP 探测端口（默认主端口 + 1，`--probe-port` 可改，0 = 不开），只回答已登录用户加密的 PING，
    告诉客户端「从这个端口看到的你的地址」。客户端用打洞的同一个套接字分别问主端口和探测端口：两次地址一样 = 好打洞；
    端口不一样 = 对称型 NAT，差得不多（≤ 64）算端口可预测。结果随 `P2pEnable` 告诉服务器，转给同频道的人。
  - **端口预测**：对方是可预测的对称型 NAT 时，每轮都朝它最近分配的端口按步长往后猜 16 个端口打；另外 2 秒还没打通就顺带试对方公网端口上下各 8 个。
  - **两边都对称、且有一边端口随机**：基本打不通，直接显示「打不通·走服务器」，不再白等 15 秒（之后每 2 秒仍试一次，以防判断错）。
  - 对方地址变化（换网络、UPnP 映射成功）时立即重新快速打洞；从意外地址收到合法打洞包也会直接采用（对端反射地址）。
- 仍打不通的成员（两边都是严格的对称 NAT 等）自动走服务器中转，用户无感知；直连断开 4 秒后也会自动回到中转。
- **直连不稳自动切中继**：每 0.5 秒测一次直连的延迟 / 丢包 / 抖动（统计最近 10 秒）。丢包 ≥15%、平均延迟 >350 ms 或抖动 >80 ms
  时自动改走服务器中转，名字下显示黄色「不稳·中转」；之后至少中转 30 秒，并且连续稳定 10 秒才切回直连，避免来回跳。
  直连断过的人重新打通后也先中转观察一段时间。链路在中转期间继续测量，右键成员可看实时数值。
  服务器只给「没直连的人」转发，频道里只剩自己时完全不发语音。
- 直连包用**两人之间的端到端成对密钥**加密（见下文「端到端加密」），外观和服务器流量一样是全随机字节。
- **代价**：同频道开启了 P2P 的成员能看到你的 IP 地址。不想暴露就关掉这个开关，只走服务器中转（服务器也不会把你的地址给任何人）。
- **按上行带宽分配**（设置 → 网络 →「直连上行预算」，默认 15 Mbps，1–100 可调）：直连要给每个人各发一份，
  所以客户端按预算决定直连哪些人——**语音优先**（约 0.06 Mbps/人），剩下的给屏幕共享画面（按码率 ×1.05 计）；
  只要有人不直连就要多传一份给服务器，这份也计入预算；同等条件下优先直连延迟低的人。语音和画面分开分配，分别告诉服务器不用再转发给谁。
  例：20 人频道语音全部直连约 1.1 Mbps；共享 1080p60 时 15 Mbps 预算大约够直连 1–2 个观看者，其余观看者经服务器（服务器只收你 1 份再分发）。
  名字旁「⇄ 23 ms」彩色 = 正在直连；灰色 = 已打通但超出预算，你的声音经服务器转给他。

带宽估算（每路说话的人，含 IP/UDP 与加密开销）：原 ADPCM ~94 kbps → 现 Opus ~53 kbps。

### 成员中继

两个人之间打不通直连（或者直连不稳）时，与其走服务器，不如让一个**和两人都直连良好、延迟最低**的队友转发。

- **上报**：每个客户端每 2 秒告诉服务器：到服务器的延迟、每条稳定直连的延迟 / 丢包 / 抖动、还能帮别人中转几路
  （按「直连上行预算」扣掉自己的开销后剩下的，每路 0.06 Mbps，最多 8 路；设置 → 网络 可以关掉）。
- **规划**（服务器，`crates/voc-server/src/relay.rs`）：对每条需要中转的 A→B，候选中继 R 必须
  ① A 正在直连发语音给 R；② R 到 A、R 到 B 都是稳定直连（丢包 ≤ 3%、抖动 ≤ 30 ms）；③ R 还有名额；
  ④ 比服务器中转至少快 20 ms。延迟按往返算（和直连的「⇄ 23 ms」是同一种数）：
  经 R = R–A 往返 + R–B 往返 + 4 ms 转发开销；经服务器 = A–服务器往返 + B–服务器往返。
  多个候选选最快的；已有路线只要仍有效、且不比最优慢 30 ms 以上就保留，避免来回切换。名额紧张时收益大的路线优先。
  每条路线同时带上两种延迟，客户端拿来做对比显示。
- **转发**：服务器把路线发给频道里每个人，并停止转发这些路线。R 收到 A 直连发来的语音包后，原样转给 B
  （R 只转发「对方自己的」包，不转发转来的包）；A 发现剩下的人都能经直连或中继送到时，就不再给服务器发语音。
- **安全**：语音包在 A 端已经端到端加密，R 本来就是频道成员、能听到 A，所以不会多泄露任何东西；
  A 和 B 互相看不到对方的 IP。
- **故障恢复**：R 掉线或链路变差，下一次上报（≤ 2 秒，直连判断断开需要 4 秒）就会撤销路线，服务器恢复转发；
  旧版客户端不上报，不会被安排中继，也不会被当作中继，和新版混用没有问题。
- 界面：对方名字下显示「↪ 经 某人 62 ms」（按延迟上色），悬停或右键可以看线路对比：
  经队友中转 / 经服务器中转（慢多少）/ 直连状态（打不通、不稳定的延迟丢包抖动、或超出上行预算）。
  你自己名字下的「🔁 中继 N 路」表示你在帮别人中转，悬停可看每一路的延迟和比服务器快多少。
服务器带宽 ≈ 只为「打不通直连的人」转发的那部分。

## 屏幕共享

进入语音频道后，左下角「🖥 共享屏幕」：选显示器、分辨率（480P / 720P / 1080P）、帧率（30 / 60），点「开始共享」。
同频道的人名字旁会出现「📺 观看 1080p60」，点一下弹出可缩放的画面窗口，标题栏显示实际分辨率和帧率。

- **管线**：Windows Graphics Capture 采集 → 缩放 + 颜色转换（多线程）→ 编码（GPU 硬件编码器或 openh264）
  → 整帧端到端加密 → 切成 ≤1.1 KB 的分片 → 能直连的观看者 P2P 直发，其余经服务器中转（UDP 不通时走 TCP 隧道）。
- **丢包补发（NACK）**：接收端按帧号攒分片（乱序也能拼回去），缺了哪片就请求补发（UDP `NACK` 包）：
  画面是直连收到的就直接发给共享者，经服务器收到的发给服务器——服务器缓存每个共享者最近约 1 秒（4 MB）的分片，
  有就直接补给这个人，没有才转给共享者（共享者保留最近 1 秒发过的分片）。补发往返时间按实测估计，
  同一帧最多请求 3 次；约 3 个往返（150–800 ms）还没补齐才放弃这一帧，改为请求关键帧（最多每 300 ms 一次）。
  共享者是旧版本（不支持补发）时照旧：缺片就请求关键帧。
- **冗余校验包（FEC）**：共享者按「被请求补发的分片 / 发出的分片」估计丢包率：≥ 0.3% 时每 10 片加 1 个异或校验包，
  ≥ 3% 时每 5 片加 1 个；没丢包 10 秒后关掉。组内丢 1 片接收端直接算回来，不用等补发。校验包的分片号 ≥ 分片总数，
  旧版本客户端和服务器会当坏包丢掉，互不影响。本机模拟 3% 丢包：旧方式 1–4 fps（几乎一直在等关键帧），新方式 50–60 fps；10% 丢包仍有 40–50 fps。
- **逐行刷新**：编码器支持 `CODECAPI_AVEncVideoGradualIntraRefresh` 时打开（1 秒刷完一屏），关键帧间隔拉长到 60 秒，
  去掉定期整张关键帧的瞬间大流量；目前测过的 NVIDIA / AMD 编码器都不支持，照旧每 10 秒一个关键帧。
  采集和解码都只保留最新画面，跟不上就丢旧帧，不会越积越多。
- **保帧率**：码率控制不跳帧，画面变化剧烈时降低清晰度来维持你选的帧率。
- **省资源**：没人观看时不编码、不发送；服务器只转发给正在看的人，已 P2P 直连的不经过服务器。
- **端到端加密**：视频用发送者密钥派生出的独立视频密钥加密（与语音的计数器互不影响），服务器只看到密文。
- **实测**（本机 1920×1080 屏幕，经两个真实客户端链路 P2P 直连，接收端解码）：720p60 和 1080p60 均稳定 60 fps，
  1080p 编码约 13 ms/帧。实际帧率取决于 CPU 和画面变化程度。
- 码率（每位观看者，H.264 基准；HEVC × 0.75，AV1 × 0.6）：「标准」480P 0.9 / 1.4 Mbps，720P 2 / 3 Mbps，1080P 3.5 / 5.5 Mbps（30 / 60 帧）；「高」× 2.2（默认，1080P60 约 12 Mbps），「极高」× 4.5（约 25 Mbps）。低带宽模式固定用「标准」。
- **实测硬件编码**：1080p60 用 NVIDIA AV1 约 3 ms/帧（openh264 约 11 ms/帧）。
- 目前只支持共享整个显示器，不含系统声音；需要 Windows 10 1903 及以上。

### 编码器与解码器

- **自动（推荐）**：每个客户端登录时上报自己能解哪些格式，共享者在**所有观看者都能解**的格式里挑最省带宽的：
  AV1（同画质约 0.6 倍码率）> HEVC（约 0.75 倍）> H.264。有硬件编码器就用 GPU，否则 openh264 软件编码。
- **手动**：设置 → 视频（或共享窗口里）可以指定用哪块 GPU 编码（如 NVIDIA AV1 / AMD HEVC / Intel H.264），或选「软件编码」。
  选的格式有观看者不支持时会自动降到大家都能解的格式。
- **解码**：设置 → 视频 → 「硬解 / 软解」。硬解用 GPU（DXVA），软解用 CPU。AV1 只在显卡支持 AV1 硬解时才会被协商使用。
- 共享窗口和观看窗口会显示当前实际使用的编码器 / 解码器；GPU 编码出错时会自动切回软件编码，不会中断共享。
- 硬件编解码通过 Windows Media Foundation 实现，不需要额外安装驱动以外的东西（HEVC 软解需要「HEVC 视频扩展」）。

## 声音：延迟、回声消除、按键说话

- **48 kHz 全程**：采集、降噪、Opus 编码、混音都是 48 kHz，不再在 48k 和 16k 之间来回重采样。Opus 码流和采样率无关，16 kHz 的旧版客户端可以互通。
- **自适应抖动缓冲**：每个说话人单独估计到达抖动（RFC 3550 的算法），缓冲目标 = 一帧 + 3 × 抖动 + 欠载补偿，范围 20–160 ms。
  稳定的直连只攒 20 ms；播空一次补 20 ms，之后每秒回收 1 ms；网络恢复时一下子到的一堆包会被丢到只剩目标量。
- **声卡缓冲 10 ms**：采集和播放都先试 10 ms，设备不接受或 2 秒内欠载 / 溢出超过 5 次就退回系统默认。编码和收包线程登记为 Windows「Pro Audio」多媒体线程。
- **嘴到耳延迟**：右键成员显示估算值 = 对方采集与编码 + 当前线路的单程网络延迟 + 抖动缓冲 + 你的声卡。
- **回声消除**：sonora（WebRTC AEC3 的纯 Rust 实现）。播放回调把即将播放的混音作为远端参考，麦克风每 10 ms 一帧先消回声再降噪。模拟外放测试中回声被压低约 60 dB。
- **按键说话**：用 GetAsyncKeyState 查全局按键状态（不装键盘钩子），游戏在前台也有效；支持键盘键和鼠标中键 / 侧键；松开后多发 200 ms。
- **进出提示音**：两声分开的「噔、噔」，进入低→高，离开高→低。

## 手动线路

右键队友 →「和他之间的线路」，按人选择（按昵称记在配置里）：

- **自动**：现在的行为（直连不稳、绕远、超出上行预算时走服务器或队友中转）。
- **强制 P2P 直连**：只要打通了就直连，不看稳定性、绕远和上行预算；打不通时仍走服务器，保证听得到。
- **走服务器**：不和他打洞（他的直连包直接忽略），客户端在 LinkStats 里带上 `via_server`，服务器规划成员中继时跳过这两人之间的路线，
  两个方向的语音都经服务器。在服务器收到新选择之前，发送端照样给服务器发一份，不会断音。

诊断信息里列出同频道每个人的加密状态（成对密钥、收到他的语音密钥、我的密钥已发给他）、我的声音发给他走哪条线、
手动线路、最近 3 秒有没有收到他的声音，以及麦克风状态（闭麦 / 按键说话 / 电平 / 是否正在发送）。
麦克风连续 5 秒给的全是 0 时聊天框上方提示检查 Windows 的麦克风隐私设置。

## 网络自检

设置 → 网络 → 网络自检，只用连接时已有的测量，不额外发包：

- **UDP**：通 / 时断时续 / 不通（连上 6 秒还没收到服务器的 UDP 回复才下结论）。
- **到服务器的延迟和丢包**：每秒一次 UDP ping，丢包率按最近 30 次里发出 1.5 秒还没回的算。
- **公网地址**：客户端的 PING 末尾带一个标记字节，新版服务器就在 PONG 里附上它看到的客户端地址（IPv4 4 字节 / IPv6 16 字节 + 端口）；
  旧服务器原样回显，旧客户端不带标记，互不影响。
- **NAT**：服务器开了探测端口时显示测出的准确类型（没有 NAT / 好打洞 / 对称型但端口有规律 / 对称型端口随机）；旧服务器退回粗略判断：公网地址就在本机网卡上 = 没有 NAT，公网端口和本地端口一样 = 端口保持，否则提示可能是对称型。
- **端口映射**：用了哪种协议、映射到哪里；映射出的地址和服务器看到的不一样 = 上游还有一层 NAT。
- **建议**：UDP 被封、丢包、延迟高、运营商级 NAT、路由器没开 UPnP、有人打不通时，分别给出大白话的建议。
- 「复制诊断信息」里也带上这些结论，但去掉了 IP 地址。

## 低带宽模式

设置 → 网络 → 低带宽模式：语音 24 → 12 kbps、伴奏和共享声音 64 → 32 kbps（编码器即时切换，不用重进频道）、
屏幕共享最高 480P 30 帧、看别人的共享默认选「流畅」。

## 私聊

- 右键成员 →「私聊」，聊天区上方出现对话标签，有未读计数。对方在任何频道（或不在频道）都能收到。
- 文字：端到端信封 BLOB_DM，用两人的成对密钥加密，只发给对方；旧版客户端不认识这种信封，直接忽略。
- 图片：先发 `FileTarget { id, to }` 告诉服务器这张图只转给 to，再按普通图片分块上传；密钥信封是 BLOB_DM_IMAGE。
  服务器在 Welcome 里带上 `features`（`dm_file`、`pong_addr`），旧服务器不支持私聊发图时客户端会提示，发文字不受影响。
- 阅后即焚：只在内存里；点标签上的 ✕ 或关掉 VOC 时把内容覆盖成 0 再释放。按昵称记对话（重连后 id 会变）。

## @提及、通知和表情回应

- 建立端到端加密后，双方互发一次能力公告（`BLOB_HELLO`，`{"features":["chat2"]}`）。之后聊天改发带编号的 `BLOB_CHAT2`
  （`{id, text, dm}`，编号 = 发送者生成，从登录时的毫秒时间起递增），旧版本仍收纯文字 `BLOB_CHAT` / `BLOB_DM`。
- **表情回应**：`BLOB_REACT`（`{from, id, emoji, on, dm}`），只发给认识的新版本；只认 6 个固定表情，别的忽略。回应和消息一起只在内存里，阅后即焚。
- **@提及**：按文字判断（消息里有「@我的名字」，后面不紧跟字母数字），不需要协议支持，旧版本发来的也认。
  被 @ 或收到私聊、而 VOC 窗口不在前台时：安装版弹 Windows 通知（WinRT ToastNotification，需要 MSIX 的应用身份，绿色版弹不了），
  任务栏图标闪烁，托盘图标加红点、提示里显示未读条数，回到窗口清零。设置里可以关掉通知。
- **个人资料**（`BLOB_PROFILE`）：正在放伴奏的程序名只端到端发给成员，服务器那边只知道「在放伴奏」（旧版本成员看到的也是「伴奏」）。

## 隐私：谁能拿到我的 IP

- 只有同频道、同样开了 P2P 的人能拿到你的公网地址；关掉 P2P 谁都拿不到（所有声音和画面经服务器）。
- 右键某人选「走服务器」：客户端发 `P2pHide`，服务器不再把你们俩的地址互相转告（以前只是客户端自己不打洞，地址照样会发过去）。
- 局域网地址（私有 IPv4、运营商级 NAT 地址、IPv6 本地 / 链路本地）只发给公网 IP 和你相同的人（同一个局域网）；公网 IPv6 照常发。
- 服务器仍然知道：谁在线、昵称、在哪个频道、IP、闭麦状态、谁和谁在通话、流量大小。昵称目前还是明文给服务器
  （登录、授权码、身份核对都按昵称），要对服务器隐藏昵称需要重做身份核对，暂未做。

## 图片与阅后即焚

- 每张图随机生成 256 位密钥，按 48 KB 分块用 ChaCha20-Poly1305 加密（nonce = 块序号，附加数据 = 图片 id），只上传一份。
  密钥和图片信息用成对密钥加密后发给同频道的每个人（端到端信封 BLOB_IMAGE），服务器只看到密文。
- 服务器把块（TCP 的 KIND_FILE 帧）边收边转给发送者所在频道的其他人，不保存；每人同时最多传 2 张，某个接收者积压超过 8 MB 就不再给他发（防内存被撑爆）。旧版客户端和服务器会忽略这种帧。
- 原图 ≤ 20 MB 且是 PNG / JPEG / GIF / WebP 就原样发；更大的缩到 4096 px 以内转 JPEG。解码限制最大 16384 px、768 MB 内存，在后台线程进行。
- **阅后即焚**：聊天和图片只在内存里。断开、重连、切换服务器时保留，关闭 VOC 时把文字和图片缓冲覆盖成 0 再释放；不提供图片另存。
  限制：已经上传到显卡的贴图由图形驱动管理，VOC 释放后不能保证被覆盖；对方仍可以截屏。

## 伴奏与屏幕共享声音

- 用 Windows 的进程回环录音（WASAPI Process Loopback，需要 Windows 11）：伴奏「只录某个程序」，屏幕共享声音「录除了 VOC 自己以外的全部」（所以队友的说话声、提示音不会被录回去）。
- 编码：Opus 音乐模式，单声道 64 kbps，带内 FEC；程序连续 0.5 秒没声音就不发。
- 加密：从语音密钥用 HKDF 各派生一把伴奏密钥和共享声音密钥，有自己的计数器和 64 帧防重放窗口，不打乱语音的帧序号。
- 传输：新的 UDP 类型 MUSIC（同频道所有没静音的人，发送者闭麦也照转）和 SHARE_AUDIO（只给观看者）。能直连的直接发，其余经服务器；暂不走成员中继，走 TCP 隧道的人收不到。
- 接收端每人一路单独混音、单独调音量。正在看某人带声音的屏幕共享时，他的伴奏已经在共享声音里了，单独那一路不再播放，避免听到两遍
  （Windows 的「排除」只能排除一个进程，已经用来排除 VOC 自己，所以在接收端处理）。
- 本地监听音量：录音会跟着这个程序在音量合成器里的音量变（实测），所以调小本地音量时把程序音量调小、发送增益按比例补回来，别人听到的不变；最低 5%，停止伴奏时恢复原音量。

## 屏幕共享：显卡直通与码率自适应

- **显卡直通**：硬件编码器和画面在同一块显卡上时，画面不拷回内存。采集线程把每帧拷进一张带 keyed mutex 的共享纹理；
  编码线程在同一块显卡上用自己的 D3D11 设备（开了视频支持）打开它，用视频处理器缩放并转成 NV12（BT.601 有限范围，和 CPU 路径一致），
  纹理直接交给 Media Foundation 硬件编码器。编码端忙时采集端拿不到锁就丢帧，不排队。任何一步失败都退回原来的 CPU 路径。
  实测 1080p AV1（NVIDIA）：解码出的颜色和 CPU 路径一致，每帧编码 < 1 ms（CPU 转换约 2 ms），打游戏时不抢 CPU。
- **码率自适应**：只调「流畅」层——每秒检查一次，观看者一秒内要关键帧 ≥ 2 次或匀速队列有包过期 → 降到 70%（最低 30%）；连续 4 秒正常每秒回升 10%。「原画」层固定按设定码率（选原画的人要的就是清楚，丢包靠补发和冗余兜住，网络实在扛不住的自己切「流畅」）。硬件编码器通过 ICodecAPI 即时调整。
- **语音优先**：画面包经匀速发送线程（画面码率 3 倍、至少 4 Mbps 的令牌桶，超过 250 ms 的丢掉），语音包直接发，不会排在关键帧后面。
- **全屏观看**：双击画面或点「全屏」，整个窗口只显示画面，鼠标 2 秒不动隐藏工具栏，Esc 退出。
- **观看端选画质（低画质层）**：共享者在 ShareStart 里声明支持分层（simulcast）后，观看者可以在 Watch 里要低画质层，
  观看中再发一次 Watch 就能切换。服务器在 Watchers 里告诉共享者哪些人要低画质，共享者另开一个 360P 编码器（帧率同原画，约 0.45 Mbps），
  哪一层没人看就不编码。低画质层的分片 flags 带 VIDEO_LOW 位、帧号单独计，服务器按层只转给对应的人；
  接收端发现换层就从新一层的关键帧重新开始。共享者是旧版客户端时服务器不分层，要低画质的人照收原画。
  显卡直通时同一帧要转两次：第一次转完把 keyed mutex 留在「编码端」，第二次转完才还给采集端。
  两层都有人看时低画质层尽量用和原画同一种格式（实测同一块 NVIDIA 显卡上同时开 H.264 和 AV1 两个编码器时，低画质层解不出来）。
- **观看端选画面线路**：观看窗口里「自动 / P2P / 服务器」，通过 `Watch.route`（0 / 1 / 2）告诉服务器，
  服务器在 `Watchers.direct` / `Watchers.server` 里转告共享者。共享者分配画面直连时：选了服务器的不直连；
  选了 P2P 的只要打通了就直连，不受上行预算限制；其余照旧。观看端按收到画面的来源显示「⇄ 直连中 / 经服务器」。
  只影响画面和共享声音，语音线路另外在右键菜单里选。
- **没人看时也要还纹理**：共享开始后没人看（或暂时断线）时编码线程不编码，但必须把显卡直通的共享纹理还给采集端；
  0.3.0–0.4.1 漏了这一步，「先开共享、过一会儿才有人看」时画面永远停在「正在等待画面」。
- **选编码器**：同一种格式有几块显卡都能编时，优先用画面所在的那块（这样才能走显卡直通）；跳过某帧显卡画面时会把共享纹理还给采集端，
  否则采集端一直拿不到锁、之后的画面全部卡住。

## 稳定性：重连、托盘、设备热插拔

- **断线自动重连**：网络断开按 1、2、5、10、20、30 秒递增重试，连上后回到原来的语音频道；被服务器踢下线（吊销、顶号）不重连。
- **快速切换线路**：直连对端 1.2 秒没消息就先改走服务器 / 中继；到服务器的 UDP 1.5 秒没回 pong 时语音同时也走 TCP 发一份。直连明显比经服务器绕远时不用直连。
- **托盘**：关窗口缩到托盘，网络和语音照常（这部分逻辑在 eframe 的 `App::logic` 里，窗口隐藏时也会运行）。
- **开机自启**：安装版用 MSIX 启动任务，绿色版用当前用户的 Run 注册表项；开机后自动登录上次的服务器、回到上次的频道。
- **设备热插拔**：后台每 2 秒查一次设备列表和默认设备；选的设备拔掉就用系统默认，插回来再切回；设备出错也会重新打开。
